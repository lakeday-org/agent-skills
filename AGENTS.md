# Agent instructions

Rules for coding agents working in this repository. `CLAUDE.md` is a symlink to this file.

## What this repository is

The Lakeday skill, hook, and MCP-configuration source for Claude Code, Codex, and Cursor. It is
structured like `motherduckdb/agent-skills`: canonical `skills/` with a `catalog.json`, generated
`plugins/` per harness, and manifests at the root.

## Layout

- `skills/<name>/SKILL.md` — canonical skills. Edit these, never `plugins/`.
- `skills/catalog.json` — index; descriptions must equal frontmatter.
- `hooks/` — the ALWAYS-mode capture runtime and hook configs. Node ≥ 20. The hook imports the
  published `@lakeday-org/worker-js/learning` package directly.
- `mcp/` — MCP server declaration.
- `plugins/` — generated by `npm run build`. Do not hand-edit.
- `docs/` — install matrix, authoring guide, knowledge-capture design.
- `tests/` — `node --test` suite with an in-memory Lakeday (`tests/fake-lakeday.mjs`).

## Rules

- Product truth is the Lakeday monorepo (`../lakeday`): MCP tools in
  `edge-router/src/mcp_tools.ts`, contracts in `docs/`. Do not document tools that do not exist
  there, except the assumed additions listed in `docs/knowledge-capture.md`.
- Every change to `skills/`, `hooks/`, or `mcp/` is followed by `npm run build`; commit the
  regenerated `plugins/`. The build bundles the hook and its SDK dependency into each plugin,
  so installed plugins do not need a post-install dependency fetch.
- `npm run check` (validate + tests) must pass before a PR.
- Hooks must stay fail-open and must never read or write CLI credentials. They obtain the active
  token by invoking `lk auth token --json`; service identities may use `LAKEDAY_API_KEY`.
- Follow `docs/skill-authoring.md` for new skills; add a catalog entry and a test if the skill
  changes hook behavior.
- Keep prose plain: no marketing copy in skills, exact identifiers, numbered workflows.
